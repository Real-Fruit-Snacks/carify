carify

Convert video for Uconnect USB playback, via ffmpeg

Uconnect head units in Chrysler, Jeep, Dodge and Ram vehicles play MP4 files from a USB stick, but only 8-bit H.264 at 720p or smaller with AAC stereo audio. carify probes the file, re-encodes only the streams that don't comply, and copies the result onto the stick.

curl -fsSL https://raw.githubusercontent.com/Real-Fruit-Snacks/carify/main/install.sh | sh
irm https://raw.githubusercontent.com/Real-Fruit-Snacks/carify/main/install.ps1 | iex
Needs ffmpeg on your PATH: winget install Gyan.FFmpeg, sudo apt install ffmpeg, brew install ffmpeg.

Why

"Unsupported file", or no sound

That's what a Uconnect unit shows for anything outside its narrow format. I wrote carify so I could stop re-learning the ffmpeg flags: one command per file, and the stick is ready.

A file that already complies takes seconds, because its streams are copied. A re-encode takes as long as libx264 needs on your machine.

How it works

What happens to a file

Nothing is scaled up, and nothing that already plays is touched.

  1. ffprobe reads the first video stream (cover art is skipped) and the first audio stream.
  2. Video is copied when it is H.264, yuv420p, Baseline/Main/High, level 4.1 or lower, and fits 1280x720. Otherwise it is re-encoded with libx264 -preset veryfast -crf 20 at High 4.1 and scaled down to fit, aspect ratio kept.
  3. Audio is copied when it is AAC with two channels or fewer. Otherwise it becomes AAC stereo at 160 kbps. A file with no audio is converted silent, with a warning.
  4. Subtitles, attachments and extra audio tracks are dropped.
  5. The MP4 is written with +faststart to a hidden .part file and renamed when ffmpeg finishes, so a cancelled run leaves nothing half-written.
  6. If a stick labelled MOVIES is mounted, the file is copied onto it. Rename your stick once and you never drag files again.

Usage

One file per run

# bash: Linux, macOS, WSL
carify movie.mkv                # writes movie-car.mp4 next to it
carify movie.mkv ~/out.mp4      # explicit output path
carify --force movie.mkv        # overwrite an existing output
carify --max-height 1080 movie.mkv
carify --no-usb movie.mkv       # don't copy to the stick
# Windows PowerShell 5.1 and PowerShell 7
carify.ps1 movie.mkv
carify.ps1 -Force -MaxHeight 1080 movie.mkv
carify.ps1 -NoUsb movie.mkv
Get-Help carify.ps1 -Full

# a whole folder
Get-ChildItem *.mkv | ForEach-Object { carify.ps1 $_.FullName }

Configuration

Flags and environment

The installers also read CARIFY_BIN (install folder) and CARIFY_REF (a tag such as v1.1.1 instead of main).

SettingDoes
--max-heightLargest frame height, default 720. Width limit is height x 16/9. Try 1080 if your unit handles it.
CARIFY_USB_DIRCopy to this folder instead of looking for a MOVIES stick
CARIFY_THEMEdayshift for light terminal backgrounds
NO_COLORAny value turns colour off

Tested on

  • Ubuntu 24.04 · bash 5.2 · ffmpeg 6.1.1 (all 40 checks in tests/run.sh)
  • CI on every push: Ubuntu (bash, PowerShell 7), macOS (bash 5 and the system /bin/bash 3.2), Windows (PowerShell 7 and Windows PowerShell 5.1)
  • Not tested: a list of head units by model year. The limits are the common denominator that has worked across Uconnect generations, not a published spec.

Known issues

  • HDR sources (HDR10, HLG) are not tone-mapped. carify warns, and the result looks washed out.
  • Only the first audio track is kept.
  • Subtitles are dropped, not burned in.
  • FAT32 sticks can't hold files over 4 GB. Format the stick as exFAT or use a lower --max-height.
