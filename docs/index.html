Convert video for Uconnect USB playback

Uconnect head units in Chrysler, Jeep, Dodge and Ram vehicles play MP4 files from a USB stick, but only 8-bit H.264 at 720p or smaller with AAC stereo sound. carify checks each stream against that line, re-encodes only what's over it, and copies the result onto a stick labelled MOVIES.

curl -fsSL https://raw.githubusercontent.com/Real-Fruit-Snacks/carify/main/install.sh | sh
irm https://raw.githubusercontent.com/Real-Fruit-Snacks/carify/main/install.ps1 | iex

Needs ffmpeg on your PATH: winget install Gyan.FFmpeg, sudo apt install ffmpeg, sudo dnf install ffmpeg or brew install ffmpeg. Then carify movie.mkv.

Why it exists

Anything outside that format shows up on the head unit as an unsupported file, or plays with no sound. I wrote carify so I could stop re-learning the ffmpeg flags for it: one command per file, and the stick is ready.

A file that already fits is copied, not re-encoded, so it takes about as long as reading it: dashcam.mp4 above took 0.3 s. A re-encode runs as fast as libx264 manages on your machine. road-trip.mkv, 30 s of 1080p HEVC, took 5.9 s on GitHub's runner.

Where the line is

ffprobe reads the first video stream (cover art is skipped) and the first audio stream. A stream is copied when it's inside every line in its rows, and re-encoded when it isn't.

These limits are the common denominator that has worked across Uconnect generations, not a published spec.

Usage

bash 3.2 or later: Linux, macOS, WSL

carify movie.mkv                  # writes movie-car.mp4 next to it
carify movie.mkv ~/out.mp4        # explicit output path
carify --force movie.mkv          # overwrite an existing output
carify --max-height 1080 movie.mkv
carify --no-usb movie.mkv         # don't copy to the stick
for f in *.mkv; do carify "$f"; done

Windows PowerShell 5.1 and PowerShell 7

carify.ps1 movie.mkv
carify.ps1 movie.mkv D:\out.mp4 -Force
carify.ps1 movie.mkv -MaxHeight 1080
carify.ps1 movie.mkv -NoUsb
Get-Help carify.ps1 -Full
Get-ChildItem *.mkv | ForEach-Object { carify.ps1 $_.FullName }

Tested on

  • Ubuntu 24.04, bash 5.2, ffmpeg 6.1.1: all 40 checks in tests/run.sh.
  • CI on every push: Ubuntu (bash, PowerShell 7), macOS (bash 5 and the system /bin/bash 3.2), Windows (PowerShell 7 and Windows PowerShell 5.1).
  • Not tested: a list of head units by model year. If a file played or failed on your car, an issue saying which model year and head unit is the data this project is short of.

Known issues

  • HDR sources (HDR10, HLG) are not tone-mapped. carify warns, and the result looks washed out.
  • Only the first audio track is kept. If that's commentary or the wrong language, pick the track with ffmpeg yourself.
  • Subtitles are dropped, not burned in.
  • FAT32 sticks can't hold files over 4 GB. carify says so when the copy fails; format the stick as exFAT or use a lower --max-height.
